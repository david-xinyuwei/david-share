# Level 5 exemplar alignment

The structural reference is the public
[`AI-Foundry-Custom-Code-Training`](../../AI-Foundry-Custom-Code-Training/) repository.
Its value here is the reader path, not its training-specific content or length.

| Slot | Why the exemplar has it | This repository | Deterministic gate |
|---|---|---|---|
| S0 | Establish scope and measured result immediately | Inbound Private Endpoint differential and explicit non-claims | README anchors and evidence values |
| S1 | Separate platform responsibility from customer responsibility | Foundry account boundary versus customer VNet/DNS/client | Required responsibility table |
| S2 | Connect every capability claim to evidence | 403 public, 200 private, 200 restored | `connectivity-run.json` assertions |
| S3 | Show the actual product surface | Redacted Foundry deployment fields and network-required UI | Image hash validation |
| S4 | Make the repository executable | Bicep, endpoint probe, guarded PNA control | Required path checks and unit tests |
| S5 | Present one complete measured run | One fixed endpoint/identity/payload network differential | Run contract and scenario matrix |
| S6 | Explain only the mechanism needed to interpret the run | DNS, Private Endpoint, PNA, and trust boundary | Boundary phrases in both languages |
| S7 | Put the runnable path in the main README | Account guard, what-if, deploy, private `200`, disable/save, public `403`, private `200`, restore original, conditional public `200` | Ordered fenced-command contract plus CLI entry-point test |
| S8 | Test rejection paths, not only success | Invalid PE/probe variants perform zero PATCH calls; evidence and Rule Catalog mutations fail closed | Executed behavior tests plus embedded mutation evaluators |
| S9 | Keep evidence and official sources one click away | Sanitized JSON, UI hashes, immutable doc commits | Repository validator |
| S10 | Give each directory one clear owner | `infra`, `scripts`, `tests`, `evidence`, `images`, `docs` | Required path checks |
