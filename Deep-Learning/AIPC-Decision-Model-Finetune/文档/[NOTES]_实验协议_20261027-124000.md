# 实验协议（2026-10-27 12:40 -07:00 冻结，结果出来前写定）

## 问题

一家 AI PC 厂商（虚构 Contoso PC）能否用自己的私有业务数据，把开源决策模型 Kev 调到在它的业务问题上明显更准、置信度可信，同时不丢掉通用能力？

## 数据（模拟，不是真实客户数据）

| 项目 | 设定 |
|---|---|
| 场景 A：售后工单分诊 | 状态 = 客户原话 + 设备档案（产品线、地区、保修类型、购买天数、电池循环、诊断代码）。问题：分派队列（8 选 1）、能否上门（是/否）、紧急度（4 级） |
| 场景 B：端侧助手意图路由 | 状态 = 用户原话 + 设备上下文（网络、是否企业管理、电源与电量、前台应用）。问题：调用工具（14 选 1）、是否只在本机处理（是/否）、执行前是否要用户确认（是/否） |
| 标签 | 由厂商策略代码计算（`scripts/vendor_policy.py`），不由大模型判断 |
| 文本 | 大模型按"必须表达的事实"写客户原话，禁止泄露内部代码、保修名和队列名；中文约 60%，英文约 40% |
| G1（训练与同分布测试） | 大模型 A，每个场景 1,400 条原话，约 35% 另加"只改一个设备字段、标签随之改变"的配对样本 |
| 切分 | 按原话分组哈希：训练 70% / 校准 10% / 开发 10% / 测试 10%（配对样本与原话同组，不跨切分） |
| G2（分布外测试） | 另一家厂商的大模型 B，每个场景 300 条，字段分布偏移（更多新加坡、更多离线和按流量计费网络、两件事混在一条消息里） |

## 比较对象（同一测试集、同一评测代码 `kev.benchmark`）

| 名称 | 说明 |
|---|---|
| B0 | 发布版 Kev（`@v1.0`），短问题描述，零样本 |
| B0-policy | 发布版 Kev，把厂商策略全文写进问题描述（只靠提示词） |
| FT | 在 Kev 发布版上续训：LoRA r16 + pointer head，2 epoch，lr 2e-5，batch 1 × accum 8，bf16，另混入 1,000 条 Kev 原训练集（防遗忘），校准集拟合温度 |

两个尺寸各跑一遍：Kev-0.8B、Kev-4B。

## 指标与判定（写在结果之前）

- 主指标：测试集问题级准确率；辅以 Brier、ECE、5% 错误预算下的可自动处理比例。
- 提升判定：FT 相对 B0 的配对 bootstrap 95% 区间下界 > 0（`kev.compare`）。区间跨 0 视为测不出差别。
- 分布外：同上，单独报告；分布外提升明显小于同分布时如实写出。
- 通用能力回归：transfer-v4 开发集准确率与 B0 对比，下降超过 2 个百分点视为有遗忘。
- 训练完成门：检查点落盘并记录 SHA-256 → 新进程重新加载评测 → 同一测试集前后对比 → 原始预测与指标拉回本地。
- 只有一次训练（seed 1）：结论只代表这一次，不外推为稳定提升幅度。
