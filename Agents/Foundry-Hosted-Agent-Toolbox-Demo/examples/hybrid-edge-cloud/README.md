# Hybrid Edge-Cloud Demo

A minimal, runnable demonstration of the hybrid edge-cloud agent pattern described in [`docs/hybrid-edge-cloud.md`](../../docs/hybrid-edge-cloud.md).

## What it shows

| Step | Where | What happens |
| --- | --- | --- |
| 1 | Edge (this Python process) | Captures 24 h of fake indoor air-quality sensor data deterministically. Writes a task contract to `contract.json`. |
| 2 | Cloud (hosted agent) | Reads the contract, calls `/responses` on the running hosted agent, which invokes Toolbox `code_interpreter` to compute statistics and produces a ventilation recommendation. |

The contract is the only integration point. The edge does not call the cloud's tools directly; the cloud does not see the edge's local APIs. Either side could be replaced without the other knowing.

## Files

| File | Purpose |
| --- | --- |
| `contract.py` | `TaskContract` and `Step` dataclasses (the shared state model). |
| `edge_agent.py` | The "edge" — generates sensor data + writes the contract. |
| `cloud_handoff.py` | The "cloud handoff" — reads the contract, calls the hosted agent, writes back the result. |

## Prerequisites

1. Repo dependencies installed (`pip install -r ../../requirements.txt`).
2. Hosted agent server running locally:
   ```bash
   cd ../..
   python main.py
   ```
   (Leave it running in another terminal. The defaults bind to `http://localhost:8088`.)

## Run it

```bash
cd examples/hybrid-edge-cloud
python edge_agent.py
python cloud_handoff.py
```

Inspect the contract between steps:

```bash
cat contract.json | python -m json.tool | head -30
```

## What you should see

After `edge_agent.py`:

```
[edge] Captured 24 hourly readings for 3 sensors (seed=42).
[edge] Wrote contract to contract.json
[edge] current_owner now = cloud
[edge] artifact size = 1234 bytes
[edge] Closing lid. Cloud takes over.
```

After `cloud_handoff.py`:

```
[cloud] Picked up task <id> (contract version 1).
[cloud] Pending step: Use code_interpreter to compute mean / max / min ...
[cloud] Calling hosted agent at http://localhost:8088/responses ...
[cloud] Step complete. Contract version now 3.
============================================================
HOSTED AGENT ANSWER:
============================================================
The mean CO2 is X ppm, max Y, min Z. ... Ventilation is/is not needed because ...
============================================================
```

The cloud answer is generated by the model after `code_interpreter` runs through the toolbox. The numbers in the answer are computed by Python in the toolbox sandbox, not eyeballed by the model — that is the entire point of the architecture.

## How this maps to a real scenario

| Demo piece | Real scenario equivalent |
| --- | --- |
| `simulate_sensor_capture` | Real sensor SDK on the edge device. |
| `contract.json` (file) | Cosmos DB document, Foundry session `/files`, or a small queue. |
| `cloud_handoff.py` (manual) | A signal pushed when the device commits the contract (Web PubSub, Event Grid, or a polling worker). |
| Local `http://localhost:8088` | The hosted agent's deployed Responses endpoint `{project_endpoint}/agents/{name}/endpoint/protocols/openai/v1/responses`. |
| Embedded artifact JSON | Blob URL with SAS, referenced from the contract. |

See [`docs/hybrid-edge-cloud.md`](../../docs/hybrid-edge-cloud.md) for the failure cases, the lease / TTL pattern, and the security boundary discussion.

## What this demo is not

- Not a runtime sample for the actual edge side. Real edge integration depends on the device platform.
- Not a production transport. Use Cosmos / Blob / a queue, not a local file.
- Not a security model. `policy: edge_only` artifact tagging is a convention this demo does not enforce.
