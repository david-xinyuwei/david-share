# Project Learnings — Azure Agent Skills In Action

> Format defined by the `continual-learning` skill (microsoft/skills).
> When a coding agent opens this repo, surface these at session start.

## tool_insight

- **2026-05-12** | The Azure MCP server's `mcp_azure_mcp_*` tool prefix is added by the **agent host** (VS Code, Copilot CLI). The raw server (started via `npx -y @azure/mcp@latest server start`) exposes plain names: `compute`, `quota`, `pricing`, `subscription_list`, `group_list`. Don't look for `mcp_azure_mcp_compute` in the JSON-RPC tools/list response — it's not there.

- **2026-05-12** | Composite Azure MCP tools (`compute`, `foundry`, `quota`, `pricing`, `monitor`, `role`) take **flat arguments + `command`**, not a nested JSON-string `parameters` wrapper. Example: `{"command": "compute_vm_get", "subscription": SUB, "resource-group": "winvm"}` works; `{"command": "...", "parameters": JSON.stringify({...})}` does NOT.

- **2026-05-12** | Composite Azure MCP tools require a 2-step learn-then-execute flow: first call `{"command": "learn"}` to discover sub-commands and their schemas, then call with the chosen sub-command + flat args. The `learn` step is undocumented in the README — discovered by observing error messages.

- **2026-05-12** | Foundry hosted-agent auth uses scope `https://ai.azure.com/.default` (NOT `https://cognitiveservices.azure.com/.default` which is for Azure OpenAI). Use `DefaultAzureCredential().get_token("https://ai.azure.com/.default")` for Foundry Responses API calls.

- **2026-05-12** | Foundry Toolbox MCP endpoint URL pattern: `{project_endpoint}/toolboxes/{toolbox_name}/mcp?api-version=v1`. Required header: `Foundry-Features: Toolboxes=V1Preview`. Without that header, the endpoint returns 404 even with a valid Bearer token.

## mistake

- **2026-05-12** | We initially generated PPT diagram canvases at 3840px wide, then displayed them at `width="960"` in GitHub README. That's a 4× downscale → text became unreadable (26pt → effective 6.5pt). **Fix:** PIL canvas should be 1280-1320px (1.3-1.4× the displayed width), not 3840px. Save displayable_width × 1.4 = canvas_width.

- **2026-05-12** | We claimed the PPT was generated by the `presenter` skill — wrong. The `presenter` agent in microsoft/skills is for React-based presentation MODE inside CoreAI DIY apps, NOT for generating .pptx files. Real PPT generation uses python-pptx + the `microsoft-docs` skill for fact-sourcing. Don't conflate "presenter" with "PowerPoint generator".

- **2026-05-12** | `extension_cli_install` requires `--cli-type` (enum: az | azd | func) but the `learn` schema doesn't surface this as a required parameter. The harness gets BAD_REQUEST 400. Workaround: pass `cli-type: "az"` explicitly.

- **2026-05-12** | `foundry` tool's `model_similar_models_get` returns generic `"An error occurred invoking 'model_similar_models_get'."` even with a valid AIServices account ID + valid model name. May be a preview API limitation. Don't assume this command works.

## pattern

- **2026-05-12** | When using `microsoft-docs` skill to write content, ALWAYS display the source URL on the page footer. Format: `📘 Source: learn.microsoft.com/...`. Without explicit URL display, readers can't audit. We applied this to the 14-slide PPT: every slide footer shows the Microsoft Learn URL the slide content came from.

- **2026-05-12** | When using `cloud-solution-architect` skill, follow the 7-step workflow strictly: identify requirements → select architecture style → choose tech stack → apply design patterns → cross-cutting concerns → WAF pillar review → ADRs. Skipping any step produces "Azure service shopping list" instead of an architecture.

- **2026-05-12** | When using `mcp-builder` skill, always set tool `annotations: {readOnlyHint: True}` for read-only tools. This is critical for safety harnesses to know which tools can be auto-executed vs which need user approval.

- **2026-05-12** | Repo image rendering on GitHub README: PIL canvas width = displayed width × 1.3-1.4. Examples: width="960" → canvas 1280px; width="800" → canvas 1100px. Always wrap with `<div align="center"><img width="..."/></div>` for centering.

## preference

- **2026-05-12** | Each `skill-demos/<skill-name>/` directory MUST contain: (1) the actual deliverable file (.md, .ts, .py, .pptx), (2) a README.md with: what was produced, reproducible prompt, skill guidance enforced, source URL.

- **2026-05-12** | Per-skill verification format: don't describe the skill — USE the skill to produce something real, then document the prompt that would reproduce it. Reader should be able to copy the prompt + load the same skill + reproduce the artifact.

- **2026-05-12** | Repo README should render skill outputs INLINE (not just link to subdirs). Customer should see deliverable highlights without clicking through.

## How a coding agent uses this file

1. **At session start**: agent reads `.copilot-memory/learnings.md` (this file) — surfaces relevant entries.
2. **During work**: when about to call an MCP tool / write infrastructure code / generate visuals, agent checks for matching entries and pre-applies the lesson.
3. **After task completion**: agent appends new learnings via `INSERT INTO learnings ...` (via the hook) or by editing this file directly when the lesson is human-meaningful.
4. **Compaction**: hook prunes entries older than 60 days with low hit count — keep the file lean.
