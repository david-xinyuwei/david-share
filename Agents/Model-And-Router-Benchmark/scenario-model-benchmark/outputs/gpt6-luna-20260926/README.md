# GPT-6 Luna follow-up: every arm re-measured in one session

2026-09-26 · Sweden Central · the same 17 assistant prompts, VM and resource as the [2026-09-09 matrix](../../README.md), plus GPT-6 Luna at every reasoning effort it accepts.

## Summary

- **GPT-6 Luna `none` is the new default low-latency tier.** In 85 back-to-back pairs against GPT-5.6 Luna `none` (order alternated), time to first token P50 was **544 ms vs 743 ms** (ratio 0.73, 95% CI 0.69–0.78; faster in 65/85 pairs and 14/17 prompts). End-to-end P50 was 1228 vs 1541 ms. It cost **65% less** per request ($0.112 vs $0.323 per 1,000).
- **Quality is on par, not better.** Two cross-vendor blind judges found no significant per-prompt difference between GPT-6 Luna and GPT-5.6 Luna at any effort.
- **Only `none` is a robust first-token win.** At `low` and `high` the TTFT gap is inside the noise (ratio CI 0.75–1.07 and 0.77–1.16), though GPT-6 Luna still finishes first in most pairs (57/85 and 63/85). Tails differ in both directions at `none`: TTFT P95 2039 vs 1000 ms (GPT-6 wider), E2E P95 7024 vs 12427 ms (GPT-6 narrower).
- **The service itself moved.** The same GPT-5.6 Luna deployment was faster than on 2026-09-09, which is why every arm was re-measured instead of comparing a new model against old numbers.

## Interleaved A/B: is the speed difference real?

The matrix runs arms one after another, so each arm owns a different half hour. Here every GPT-6 Luna request has a GPT-5.6 Luna partner on the same prompt sent immediately before or after it. The P50 ratio CI resamples prompts, not requests; the sign tests count pairs and prompts where GPT-6 Luna was faster.

## Quality

GPT judges were ruled out: `gpt-5.6-terra` is a generation older than GPT-6 and `gpt-6-astra` is GPT-6 Luna's own family, and the repository's judge rules reject both. Two Claude judges scored the same 289 answers (first measured answer per arm × prompt) with the unchanged five-dimension rubric `v2-toolless-2026-09-10`:

- **Judge A, Claude Opus 5.5**, via a GitHub Copilot agent: answers anonymised and shuffled, scored in 8 independent batches of 36–37 with the rubric verbatim. Batch leniency varied (batch means 4.21–4.86); every batch is a random mix of arms, so this adds noise rather than favouring one model.
- **Judge B, Claude Opus 4.6**, through the Foundry Anthropic Messages API with `judge.py` (extended thinking, 4,096-token budget), as an independent cross-check.

Agreement: item-level Pearson 0.69 over 289 answers. Both put GPT-4o mini last; Judge B is more lenient overall (4.76 vs 4.63) and disagrees most on GPT-5 mini `minimal` (4.14 vs 4.64).

## Limitations

- 17 synthetic prompts, single turn, concurrency 1, one region, one evening. Not a capacity or SLA test.
- GlobalStandard does not pin the GPU region; the resource region is a fact, the serving region is not observable.
- TTFT includes network, queueing and any reasoning before the first text token; it is not pure model time.
- Prompts PA01, PA03 reproduce an internal meeting transcript; their answer text and judge justifications are withheld in this public copy (numbers, scores and `response_sha256` unchanged), as in [public_redaction.json](../public_redaction.json).
