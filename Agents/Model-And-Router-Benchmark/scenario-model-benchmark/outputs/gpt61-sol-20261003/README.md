# GPT-6.1 Sol follow-up: where the bigger reasoning model earns its price

2026-10-03 · Sweden Central · the same 17 assistant prompts, VM and resource as the [2026-09-26 GPT-6 Luna run](../gpt6-luna-20260926/README.md), plus an interleaved A/B against GPT-6 Luna, an exact-answer probe and a prompt-cache check.

> Generated by [`scripts/build_gpt61_sol_report.py`](../../scripts/build_gpt61_sol_report.py) from the files in this folder. Do not edit by hand; `--check` fails if this page and the evidence disagree.

## Summary

- **On the assistant prompts GPT-6.1 Sol is slower and dearer than GPT-6 Luna, not better.** In 85 back-to-back pairs at `low` (order alternated), GPT-6.1 Sol reached the first token in **1271 ms vs 775 ms** for GPT-6 Luna (P50; ratio 1.64, 95% CI 1.27–2.30) and finished in 4084 vs 1498 ms; it was faster in 14/85 pairs. At list price its `low` arm costs $2.37 per 1,000 requests; GPT-6 Luna `none` cost $0.11 on 2026-09-26.
- **Quality on these prompts is already saturated.** The Claude Opus 4.6 judge gave GPT-6.1 Sol 5.00 / 4.85 / 4.95 out of 5 at `low` / `medium` / `high`; GPT-6 Luna scored 4.81–4.84 on the same judge on 2026-09-26. Short assistant turns do not separate these models.
- **Where it does earn its price: the exact-answer probe.** Asked to find the unique 9-of-24 invoice subset that reconciles to a given total, GPT-6.1 Sol `high` returned the exact answer in 2/3 runs (1 spent the whole 40,000-token output cap reasoning and gave no answer), `medium` 1/3, `low` 0/3. Wrong answers: 0; when it did not solve the task it declined. With the cap raised to 100,000 tokens `high` solved 3/3, and no run needed more than 21,808 output tokens: the cut-off run was variance, not a budget wall (median $0.12 per solve). GPT-6 Astra `high` solved 3/3 at the 40,000 cap, median $0.46 per solve.
- **Prompt caching behaves like the rest of the family.** Re-sending the same ~1,050-token request hit the cache on 9/18 repeats and cut steady-state cost by 18% at list price (cache read 0.1×, write 1.25×).
