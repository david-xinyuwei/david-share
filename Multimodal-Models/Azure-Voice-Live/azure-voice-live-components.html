Azure Voice Live 全组件参考表

听 · 想 · 说 三层拆解  |  可读命名 ↔ 官方 API 值对照  |  生成日期 2026-08-12

命名约定：「展示名」是为了可读性自定的写法（Azure-Speech-STT / Azure-Speech-TTS-standard）， 写 JSON 时必须使用「API 实际值」那一列，展示名不是合法枚举值。
③ 层有两种本质不同的性质 —— 很容易看错：
原生发声（openai / azure-realtime-native）—— 模型是 speech-to-speech 端到端，音频进、音频出， 根本没有独立 TTS 环节；voice.type 在这里只是“选哪个声线”。
外接合成（azure-standard / azure-custom / azure-personal / avatar-voice-sync）—— 文本真的送进 Azure Speech 引擎合成，端到端被打断，因此产生额外延迟。
这也解释了为什么 instructions 只对 OpenAI voice 生效（语音是推理的一部分），而换 Azure 音色会加延迟（插入了真实 TTS 环节）。

二、Azure Speech 在 Voice Live 里的 5 个入口

1 个 STT + 4 个 TTS。 azure-speech 这个字面值只存在于 STT 配置里；TTS 侧的 Azure Speech 用 azure-* 四兄弟表示。 之所以 TTS 要拆四个，是因为每种输出的必填参数不同（endpoint_id / model / 无）， 这是 tagged union 设计，一个名字承载不了。

六、配置示例（必须用官方值）

A · Cascade —— 纯文本 LLM，① 和 ③ 都要配

// URL: wss://<resource>/voice-live/realtime?api-version=2026-04-10&model=gpt-4.1
{
  "input_audio_transcription": {
    "model": "azure-speech",                  // Azure-Speech-STT
    "phrase_list": ["Contoso", "Fabrikam"],
    "custom_speech": { "zh-CN": "<model-id>" }
  },
  "voice": {
    "type": "azure-custom",                    // Azure-Speech-TTS-custom
    "name": "zh-CN-BrandNeural",
    "endpoint_id": "<your-endpoint-guid>"
  },
  "turn_detection": { "type": "azure_semantic_vad_multilingual" }
}

D · Phi 低成本 —— SLM 自带耳朵，只补 ③

// URL: ...?model=phi4-mm-realtime
{
  "voice": {
    "type": "azure-standard",                  // Azure-Speech-TTS-standard
    "name": "zh-CN-XiaoxiaoNeural"
  }
}

四种 TTS 的参数差异（为什么不能合并成一个名字）

// azure-standard —— 只要语音名
{ "type": "azure-standard", "name": "en-US-AvaNeural" }

// azure-custom —— 必须给训练好的 endpoint
{ "type": "azure-custom", "name": "en-US-CustomNeural",
  "endpoint_id": "your-endpoint-id" }        // ← 多了这个

// azure-personal —— 必须指定基座模型
{ "type": "azure-personal", "name": "your-voice",
  "model": "DragonLatestNeural" }             // ← 多了这个

// avatar-voice-sync —— 只要 model，不要 name
{ "type": "avatar-voice-sync",
  "model": "DragonHDOmniLatestNeural" }       // ← 没有 name
